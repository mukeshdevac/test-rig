### 2. CORE ARCHITECTURE & SELF-HEALING USB SERIAL CONNECTION
- **Communication Protocol:** Hardwired USB OTG Serial (`usb-serial-for-android` or Flutter `usb_serial`) communicating with an ESP32 Test Rig at 115200 Baud rate.
- **Robustness & Self-Recovery (Mandatory):**
  - Implement a background Heartbeat State Machine: Send `{"cmd": "PING"}` every 1000ms. Expect `{"resp": "PONG"}`.
  - If 3 heartbeats fail or physical USB disconnection occurs:
    - Automatically switch app state to `RECONNECTING` without crashing or blocking the main UI thread.
    - Launch an active background reconnect poller searching for vendor/product USB IDs every 500ms.
    - Upon re-plug, re-establish serial session, handshake with ESP32, and restore operational state seamlessly.

### 3. HARDWARE & TEST ROUTINE MAPPING (LOF TITAN S3 PCB)
The app must command the ESP32 Test Rig to execute and parse tests matching this exact LOF Titan S3 pin hardware layout:
- **UART Loopback:** TX (GPIO 17) to RX (GPIO 18)
- **SPI Loopback:** SCK (GPIO 35), MOSI (GPIO 36), MISO (GPIO 37), CS (GPIO 38)
- **I2C Bus Scan:** SCL (GPIO 8), SDA (GPIO 7)
- **Motor Drivers:** M1 (GPIO 15/16), M2 (GPIO 13/14), M3 (GPIO 11/12), M4 (GPIO 9/10)
- **Indicators:** LED1 (GPIO 47), LED2 (GPIO 48), Buzzer (GPIO 20)
- **Sensor Inputs:** S1 (GPIO 2), S2 (GPIO 1), S3 (GPIO 3), S4 (GPIO 4), S5 (GPIO 5), Ultrasonic S1 (GPIO 6), Ultrasonic S2 (GPIO 19)

### 4. OPERATOR AUTHENTICATION & GOOGLE SHEETS LOGGING PIPELINE
- **Operator Verification:** Require operator sign-in (Operator ID / PIN / Barcode scan) before unlocking test controls. Log Operator ID with every test record.
- **Offline-First Data Pipeline:**
  1. When a test completes, serialize all results (Timestamp, Operator ID, Serial Number, Overall Result, INA219 current readings, individual pin/bus results) into a local SQLite/Hive offline database queue.
  2. A background worker reads from the queue and sends HTTP POST requests to a Google Apps Script Web App Endpoint.
  3. Automatically retry failed requests on Wi-Fi drop; mark items as synced upon HTTP 200 `SUCCESS` response.
